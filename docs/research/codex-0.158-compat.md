# Codex 0.158.0 补丁及双 SDK 兼容边界（只读研究）

研究日期：2026-09-28。对应决策票：[研究 Codex 新稳定基线与现有补丁、双 SDK 的兼容边界](https://github.com/immorcoding/codex-multiprovider/issues/2)。本文不实施移植，也不宣称新版引擎或供应商在线验证已经通过。

## 基线与来源

- GitHub 当时标记的最新非预发布版是 [`rust-v0.158.0`](https://github.com/openai/codex/releases/tag/rust-v0.158.0)，标注 2026-09-28 发布；解引用 tag 的源码提交为 [`064c6b8c737f5b41d171fdda80bd9ef10ad06eb3`](https://github.com/openai/codex/tree/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3)，Rust workspace 版本为 `0.158.0`（[`codex-rs/Cargo.toml`](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/Cargo.toml#L153-L157)）。实施前须再次查稳定 release 并锁定 SHA，不能以此日期的“最新”代表将来。
- 本仓库补丁及安装器的既有基线为 `1715e55076737158ba61d43158ede504de6d4ce1`，安装器强制精确 SHA 与干净 checkout；旧补丁的 `Cargo.toml` 和大量 `Cargo.lock` 修改把 workspace 的 `0.0.0` 填成 `0.154.0`。这属于旧发布版本的生成/发布差异，不是多供应商行为，应从新版行为移植中剥离（[本仓库补丁](https://github.com/immorcoding/codex-multiprovider/blob/29d09309630034d7b3bb617da77c987c15dd4a43/patch/model-provider-routes.patch)、[安装器](https://github.com/immorcoding/codex-multiprovider/blob/29d09309630034d7b3bb617da77c987c15dd4a43/tools/install-engine.ps1)）。本地 `E:\Projects\codex` 当前为 `multiprovider-routing` 的 `d8112e64fa7b8076392f17813d0808cc34bc3955`，不是本研究稳定版；未写入该目录。
- `0.158.0` 有用户定义的 `model_providers`、`model_provider` 和 `model_catalog_json`，但在该 tag 的 `codex-rs`/`sdk` 源码中没有 `model_provider_routes` 或 `wake_parent_on_completion` 名称（上游 [config TOML](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/config/src/config_toml.rs#L315-L327)、[模型目录字段](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/config/src/config_toml.rs#L390-L401)、[子代理通知](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/core/src/agent/control/completion.rs#L88-L111)；对整个 tag 的符号检索）。所以“已有自定义供应商配置”不等于“按模型自动路由”。

## 可观察行为对照

| 场景 | 旧补丁要求 | 0.158.0 可复用点与冲突 | 待验收断言 |
| --- | --- | --- | --- |
| 新线程选模型、未显式指定供应商 | `model_provider_routes` 选择供应商；未知供应商配置即拒绝 | app-server `thread/start` 仍接收 `model`、`modelProvider` 和原始 `config`，但上游直接把请求交给 `build_thread_config_overrides` 再加载配置；需在新版异步启动/配置层找适配点，不能假设已有自动路由（[旧补丁](https://github.com/immorcoding/codex-multiprovider/blob/29d09309630034d7b3bb617da77c987c15dd4a43/patch/model-provider-routes.patch)、[上游启动](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/app-server/src/request_processors/thread_processor.rs#L1194-L1234)）。 | 路由模型选择正确端点并在元数据记录供应商；无路由模型保留默认供应商；未知 route 配置在加载时失败。 |
| 显式矛盾供应商、会话固定与 `turn/start` 模型覆盖 | 跨供应商显式请求拒绝；恢复/单轮/子代理不能悄悄跨供应商 | 原补丁分别检查 start、resume、turn 和 spawn。上游 resume 会把持久化模型/供应商元数据合入请求，已有 `check_thread_model_provider` **只**检查当前 managed provider 约束，并非模型路由检查；新版另有 `thread/settings/update` 模型入口，不能仅覆旧 `turn/start`（[旧补丁](https://github.com/immorcoding/codex-multiprovider/blob/29d09309630034d7b3bb617da77c987c15dd4a43/patch/model-provider-routes.patch)、[resume](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/app-server/src/request_processors/thread_processor.rs#L3880-L3935)、[managed 检查](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/app-server/src/config_manager.rs#L262-L310)、[settings](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/app-server/src/request_processors/turn_processor.rs#L926-L977)）。 | 同供应商模型变更可继续；跨供应商 start/resume/turn/settings 覆盖明确拒绝；无覆盖恢复原固定供应商。 |
| `thread/fork` 与 `codex exec` | `exec` start/resume/fork 在默认供应商与模型 route 矛盾时省略显式 provider，让 app-server 决定；原补丁未单独在 app-server fork 做 route 检查 | 上游 exec 三处仍传 `Some(config.model_provider_id.clone())`，并且 fork 基于请求覆盖重建配置；因此需补全 fork 契约，而非只移植三处替换（[exec](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/exec/src/lib.rs#L1043-L1058)、[start/resume](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/exec/src/lib.rs#L1360-L1408)、[fork](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/app-server/src/request_processors/thread_processor.rs#L4975-L5000)）。 | CLI exec、fork 各自覆盖无显式、匹配、矛盾 provider；fork 与原会话固定语义须明确决策。 |
| 子代理显式模型 | 子代理继承父供应商，不能使用路由到别处的模型 | 旧落点 `core/src/tools/handlers/multi_agents_common.rs` 已移到 [`core/src/agent/child_config.rs`](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/core/src/agent/child_config.rs#L196-L244)；该处仍在选型后设置 `config.model`，可作候选落点，另须覆盖 role/default subagent model 分支。 | 跨路由拒绝、同路由接受，错误含模型和 provider；子代理默认模型/role 也受约束。 |
| 子代理完成唤醒空闲父代理 | 配置开关默认 true，完成时触发父代理新轮次 | 上游 `session` 把终结结果交 `agent_control.turn_finished`，实际通信在新的 [`agent/control/completion.rs`](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/core/src/agent/control/completion.rs#L25-L117)，目前 `trigger_turn=false`；旧改动的 `session/mod.rs` 落点不再承载发送。另有 [`AgentMessage::into_communication`](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/core/src/agent/control/delivery.rs#L16-L42) 的 `QueueOnly`/`TriggerTurn` 区分。 | 开关 true：已结束的 parent 自动收到 child 结果；false：只排队。正在运行的 parent 不重复启动；错误/中断及 detached watcher 路径不重复投递。 |
| Responses 代理转换 | 对不支持 `agent_message` 的后端降级成 user message；缺 `call_id` 的 `function_call_output` 修复成 user message；保留不可读 payload | 本仓库 [`proxy-transforms.mjs`](https://github.com/immorcoding/codex-multiprovider/blob/29d09309630034d7b3bb617da77c987c15dd4a43/tools/proxy-transforms.mjs) 和 [`deepseek-proxy.mjs`](https://github.com/immorcoding/codex-multiprovider/blob/29d09309630034d7b3bb617da77c987c15dd4a43/tools/deepseek-proxy.mjs) 是引擎外的通用 Responses 请求重写；0.158 的通信仍支持明文/加密消息，但**未验证**其真实线格式，也不能推断新供应商一定需要相同降级（[上游 delivery](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/core/src/agent/control/delivery.rs#L16-L42)）。 | 用脱敏本地 mock 观察 0.158 的请求形状，测正常 tool-call `call_id` 不变、可读/不可读 agent payload、流式事件与故障透传；再决定供应商专属转换。 |

上表中“候选落点”是源码对照推断，不是已验证的移植设计。`thread/fork`、`thread/settings/update`、role 默认模型及完成通知的 detached watcher 是旧补丁测试矩阵以外的风险，应由后续决策票定下语义与验证范围。

## SDK 边界与是否需要改 SDK

| SDK | 0.158.0 源码契约 | 最小无密钥验证与改动判断 |
| --- | --- | --- |
| TypeScript | [`CodexOptions`](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/sdk/typescript/src/codexOptions.ts#L5-L29) 支持 `codexPathOverride`、结构化 `config`、原样 `configOverrides`；[`CodexExec`](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/sdk/typescript/src/exec.ts#L73-L197) 通过 `codex exec --experimental-json`，`--model` 与 `--config` 调 patched binary。默认二进制来自 `@openai/codex` 的平台包，Windows x64/arm64 有独立包寻址（[同文件](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/sdk/typescript/src/exec.ts#L46-L61)）。 | 用 `codexPathOverride` 指向同一已编译 0.158 patched CLI，隔离 `CODEX_HOME`，mock provider 验证 start/runStreamed/resume 的路由、JSONL、错误/取消；再对默认平台包做“是否意外跑 stock CLI”防呆。现有公开 API 足以透传模型与 config，**尚无证据必须修改 TS SDK**；如果要求开箱默认使用 patched runtime，则需另定包装/发布策略。 |
| Python | [`CodexConfig`](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/sdk/python/src/openai_codex/client.py#L185-L275) 支持 `codex_bin`、`config_overrides`，启动 `app-server --listen stdio://`；[`api.py`](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/sdk/python/src/openai_codex/api.py#L135-L284) 的 thread start/resume/fork 可显式传 `model_provider` 或不传。此 tag 的 [`pyproject.toml`](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/sdk/python/pyproject.toml#L8-L24) **仍依赖 `openai-codex-cli-bin==0.153.4`**；默认包 runtime 不能当作 0.158。对自定义 CLI，版本/`generate-json-schema --experimental` 的 [`CheckoutCapabilities`](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/sdk/python/src/openai_codex/_runtime_requirements.py#L11-L66) 检查新字段。 | 显式 `codex_bin` 指同一 patched binary，隔离 HOME，在 mock app-server/provider 路径验证 initialize、start、turn/run/stream、resume/fork、错误/通知，核对生成类型是否接受响应；单列默认 `0.153.4` 依赖的版本差异。已具备供应商参数与自定义 binary，**尚无证据必须改 Python SDK**；若要求发布包默认 runtime 与 patched 0.158 匹配，则依赖/工件重建属于单独实施问题，不能以当前源码依赖宣称已配对。 |

SDK 均未在本研究中安装、编译或运行；“源码可透传”不是 ABI/协议兼容通过。上游 TS SDK [说明](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/sdk/typescript/README.md#L1-L18)明确其为 CLI 包装，Python 是 app-server JSON-RPC 客户端（[源码](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/sdk/python/src/openai_codex/client.py#L203-L221)）；因此不能用一个 SDK 的 smoke 代替另一个。

## 尚需决策/实验

1. `thread/fork` 的供应商是否必须继承并固定原会话，还是允许明确的新 provider fork？原补丁没有完整定义；新版 fork 会重建配置（[上游 fork](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/app-server/src/request_processors/thread_processor.rs#L4975-L5000)）。
2. 在 `thread/settings/update`、子代理 role/default 模型、managed config reload 下，跨 provider 模型选择是拒绝还是重新建线程？上游入口和保留配置路径不同（[settings](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/app-server/src/request_processors/turn_processor.rs#L926-L977)、[managed 检查](https://github.com/openai/codex/blob/064c6b8c737f5b41d171fdda80bd9ef10ad06eb3/codex-rs/app-server/src/config_manager.rs#L262-L310)）。
3. 0.158 真正传给目标供应商的 SSE/Responses 形状与现有代理假设是否一致？先用本地 mock 测 shape，再做目标官方服务的最小在线验证；不要把旧 DeepSeek 兼容处理自动应用给新供应商（[本地转换](https://github.com/immorcoding/codex-multiprovider/blob/29d09309630034d7b3bb617da77c987c15dd4a43/tools/proxy-transforms.mjs)）。
4. 验收分层：配置解析/路由单测、app-server start/resume/fork/turn/settings、exec、子代理 completion、TS 与 Python 各自无密钥 mock smoke；在线验证与凭据权限另行确定。此项是建议测试矩阵，尚不是通过报告。

范围边界：只针对 GitHub 开源引擎和对应 SDK；不碰微软商店桌面端、不修改 `E:\Projects\codex`，也不在本研究里加入模型实现或访问密钥。
